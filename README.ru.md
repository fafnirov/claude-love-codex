# Claude love Codex

Claude Code — оркестратор. OpenAI Codex CLI — исполнитель. Вы формулируете задачу
словами, а Claude сам решает, что сделать самому, что делегировать, проверяет
фактический дифф и тесты и возвращает один отчёт.

Смысл не в новизне, а в том, что **контекст исполнителя не попадает в ваш**.
Codex читает файлы, гоняет инструменты и тратит свои токены; Claude получает
JSON-отчёт примерно на 500 токенов. В замеренном прогоне задача стоила ~73k
входных токенов на стороне Codex и ~0.5k в контексте Claude.

```bash
~/.claude/scripts/codex-task.sh run --repo . --test "pytest -q" \
  --scope "src/api/*" "перепиши вызовы fetch в src/api на axios"
```

## Что это даёт

- **Изоляция.** У каждой задачи свой `task_id`, своя ветка и свой git worktree.
  Рабочая копия не трогается.
- **Гейт качества по фактам.** Статус считается из кода возврата, фактического
  `git diff`, кода возврата тестов, разбора рисков и границ задачи — а не из
  слов исполнителя.
- **Атомарное слияние.** Результат собирается и проверяется во временном
  worktree; ref из `--into` двигается только после успешных тестов и только
  через compare-and-swap. Провал тестов не может оставить вашу ветку изменённой.
- **Перекрёстное ревью.** Codex проверяет ваш дифф, вы — его, и замечания
  приходят с доказательствами из кода.
- **Работающие лимиты.** 3 попытки на задачу, бюджет времени, 2 одновременных
  исполнителя, тайм-ауты, защита от дублей и от «топтания на месте».
- **Журналы и ротация.** У каждой задачи сохраняются промпт, журнал событий,
  дифф, лог тестов и отчёт; `gc` чистит старое, но никогда не трогает
  незавершённые задачи, ошибки и аудит слияний.

## Требования

- [Claude Code](https://docs.anthropic.com/claude-code)
- [OpenAI Codex CLI](https://developers.openai.com/codex/cli/) с авторизацией
  (`codex login`)
- git, Python 3, bash

Проверено на Windows 11 + Git Bash с `codex-cli 0.163.0-alpha`. На macOS и Linux
должно работать, но там не проверялось.

## Установка

```bash
git clone https://github.com/<вы>/claude-love-codex.git
cd claude-love-codex
bash install.sh
~/.claude/scripts/codex-task.sh doctor
```

Установщик копирует скрипты и скилл Claude Code в `~/.claude`, а правила для
исполнителя кладёт в `~/.codex/AGENTS.md` **только если этого файла ещё нет**.
`settings.json` и ваш `CLAUDE.md` он не трогает.

Затем добавьте разрешения из [docs/PERMISSIONS.md](docs/PERMISSIONS.md), чтобы
обычные вызовы перестали спрашивать подтверждение, а `merge` и `clean`
продолжали спрашивать.

## Как пользоваться в диалоге

Со скиллом ничего вызывать руками не нужно — вы просто пишете задачу:

> перепиши вызовы fetch в src/api на axios и прогони тесты

Решение о делегировании принимает Claude. Можно управлять явно: «используй
Codex», «сделай сам», «запусти две задачи параллельно», «пусть Codex проверит
мой код».

## Команды

| Команда | Что делает |
|---|---|
| `run` | делегировать задачу (`--test`, `--scope`, `--task-file`, `--base`, …) |
| `review` | перекрёстное ревью задачи или произвольного диффа |
| `merge` | проверенное атомарное слияние в `--into` |
| `clean` | удалить worktree задачи (откажет, если там несохранённое) |
| `list` / `show` | журнал и полный отчёт |
| `stats` | статистика и суммарный расход токенов Codex |
| `recover` | незавершённые задачи и осиротевшие ресурсы |
| `gc` | ротация журналов (`--days`, `--max-mb`, `--dry-run`) |
| `doctor` | бинарь, авторизация, модель, пути |

Контракт задачи (`--task-file task.json`) содержит `goal`, `allowed_files`,
`forbidden`, `acceptance`, `test_command`, `timeout`, `max_attempts`,
`depends_on`.

## Безопасность — прочитайте обязательно

Песочница Codex **не ограничивает чтение**. Делегированная задача может прочитать
любой файл, доступный вашей учётной записи, включая `.env` и `~/.codex/auth.json`,
и записать файл за пределами worktree в доступные вам каталоги.

**Не используйте это на машинах с боевыми ключами и чувствительными данными.**

Полная модель угроз: [docs/SECURITY.md](docs/SECURITY.md).

## Самопроверка

Наборы используют тестовый двойник вместо модели и ничего не стоят:

```bash
bash tests/run-tests.sh          # детектор, лимиты, гейты слияния, параллелизм
bash tests/run-lifecycle.sh      # прерывания, сироты, восстановление, ротация
bash tests/run-merge-atomic.sh   # атомарность слияния и обновление ref
```

Что проверялось на живом Codex — в [docs/VERIFICATION.md](docs/VERIFICATION.md).
